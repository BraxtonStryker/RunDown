# RunDown

A Markdown word processor with live preview: the text being edited inside a piece of Markdown is plain, and it renders the moment that piece is closed. Part of the study apps at https://braxtonstryker.github.io/ (with QuizQrusher in `../Quiz_Qrusher/`, InfoBase in `../Class_Base/` and CwikCard in `../CwikCard/`). Hosted on GitHub Pages at `/RunDown/` (repo `BraxtonStryker/RunDown`). **v1.0.1** (2026-10-20: document tabs, blue instead of teal for the accent, icon and app switcher, wider page, sideways-scrolling tables). v1.0.0 built 2026-10-18 (Beta tag next to the name, like InfoBase and CwikCard).

## Layout
- `index.html`: the whole app. `sw.js`, `manifest.webmanifest`, `icons/` (`icon.svg` and `icon-maskable.svg` are the sources of the PNGs, rendered with headless Chrome): the installable offline app. `vendor/katex.min.js` is the same KaTeX build InfoBase uses (`Class_Base/studydb/web/vendor/`); it is loaded on demand and renders MathML only, so no KaTeX CSS or fonts are needed.
- `tools/sw_version.py`: `python -I tools/sw_version.py --sync` after changing any precached file, or the service worker won't ship the change.
- `tools/harness.py`: headless-Chrome regression harness over the DevTools protocol (stdlib only; finds Chrome or Edge). Types with real key events, so `beforeinput` fires as it does for a person; also checks IME composition, paste, views, find and replace, persistence and typing speed in a 2,800-line document. Rerun it after any editor change and extend it. `--shots DIR` saves screenshots.

## Conventions (match QuizQrusher and CwikCard)
- Single-file HTML, inline CSS and JS, vanilla JS in an IIFE, `var` and `function` style, no frameworks, no build step, nothing from CDNs (the Atkinson Hyperlegible font is inlined from CwikCard).
- Every color is a CSS custom property on `:root`, with dark values for "Match system" and `data-theme="dark"`. Font sizes are `calc(Npx * var(--fs))`. Blue is RunDown's color (since v1.0.1; it was teal): the default accent (`#1D4ED8` / `#6EA8FE`, the Blue preset), the app switcher entry, and the icon (gradient `#2F6BEA` to `#1E40AF`, details `#1D4ED8`).
- American spelling. Every localStorage, IndexedDB and cache name starts with `runDown` (`runDown:settings`, `runDown:last`, IndexedDB `runDown:app`, caches `runDown-<version>`): all of the user's GitHub Pages apps share one origin.
- Copied from QuizQrusher/CwikCard and kept in step by hand: the appearance block in `<head>`, the storage backends, Settings rows, the toast, the app switcher and the service worker. The app switcher is the same menu in all four apps (QuizQrusher, InfoBase, CwikCard, RunDown) with the four-square Home icon; keep them in step. Hidden from `file://`.
- Log each release in Help > What's new and bump `APP_VERSION`.

## How the editor works
- **One source of truth:** `src`, the document's Markdown string. The page never edits itself: `beforeinput` is cancelled and turned into `edit(from, to, text, selAfter, kind)` on `src`, which also records undo (typing, Backspace and Delete runs merge into one step, broken at spaces). IME composition is the exception: the browser edits the page, and `reconcile()` reads the lines back into `src` on `compositionend` (also the fallback for any `input` event that wasn't cancelled).
- **Every character is in the page.** Each source line is a `div.ln` (multi-line blocks wrap theirs in `div.blk` with `_lines`). Markers of a rendered piece sit in `span.mk.x` (hidden); widgets (pictures, formulas, checkboxes, the Copy button) carry `data-ns` and count as zero characters. So `domToPos` / `findIn` map page positions to `src` offsets by counting text. Hidden ranges are recorded per line in `_hid` with a role: `o` opening, `c` closing, `a` atomic (picture or formula source), `p` line prefix.
- **What renders:** `parseBlocks` (code fences, `$$` math, GFM tables, then one block per line with list depth and numbering) and `parseInline` (code spans, math, escapes, links, pictures, autolinks, then CommonMark's delimiter-run emphasis for `*`, `_`, `~~`, `==`). A fence or `$$` block without its closing line is not a block, so it stays text. A piece renders unless the collapsed cursor is strictly inside it (`s < c < e`); the cursor's line (or whole multi-line block) shows its prefix. Settings > Editing > "While you edit inside formatting": `plain` (the user's spec, default) drops the formatting of the open piece; `styled` keeps it and shows the markers. A selection, a blurred page (Esc) and Read view render everything.
- **Cursor at an edge** (`normCol`): a click or arrow landing next to hidden markers resolves outside the piece (after `c`, before `o`), so typing after bold text isn't bold. Backspace/Delete skip hidden markers and delete the visible letter; next to an atomic widget they open it instead.
- **Rendering is keyed** (`blockKey`: type, text, depth, numbering, reveal state, `renderEpoch`, view). Unchanged blocks reuse their elements in page order; identical lines (blank lines, repeated items) share a key, and the reuse must stay in order or every line gets moved (that bug cost 60 ms a key). Bump `renderEpoch` when anything other than the text changes rendering (settings, KaTeX loading, new pictures).
- **Data:** IndexedDB `runDown:app`, stores `docs` (`{id, name, text, createdAt, updatedAt, caret}`) and `assets` (pasted pictures as data URLs, referenced from Markdown as `asset:<id>`; exports inline them). Falls back to localStorage, then memory. Unreferenced assets are pruned when a document is deleted. Backups are `rundown-backup` JSON (newer copy of a document wins on import).
- **Safety:** links open only on Ctrl/Cmd+click (or a click in Read view) and only for http(s), mailto, tel, `#heading` and bare domains; `javascript:` and other schemes are dropped in exports. HTML in Markdown is shown as text, never rendered. Pasted HTML goes through `DOMParser` and is converted to Markdown, so nothing from it runs.
